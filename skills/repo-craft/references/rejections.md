# Restraint examples

These are reasons to simplify, not forbidden artifact types. The [three tests](tests-and-proofs.md) decide for this project. Explain a concern once and offer an alternative.

| Candidate | Common problem | Useful alternative |
| --- | --- | --- |
| Readiness score | Counts added artifacts as quality | Named unresolved checks and keep/skip reasons |
| Evidence index | Repeats links already clear in the README | Improve the links; keep an index only for otherwise difficult navigation |
| Generic banner | Communicates category, not behavior | Actual result, labeled illustration, or no image |
| Badge collection | Hides first use without helping decisions | Badges whose live status or destination answers a reader question |
| Tagline alone | Describes a feeling without explaining the task | Plain sentence about task and audience |
| Maturity/performance claim | No applicable evidence | Actual command, result, conditions and limits |
| Agent guide template | Repeats general advice | Specific commands, conventions and risks |
| Trailer of one instantaneous command | Makes output harder to read | Still and text transcript |
| Duplicate site | Adds maintenance without a reader benefit | Sufficient repository presentation |
| Sponsor/popularity claims among results | Blurs endorsement and evidence | Label sponsorship separately and preserve attribution |
| Profile redesign | Expands repository work into account changes | Propose only when relevant and authorized |

Badge density, palette and typography are taste. Broken links and unsupported claims are inspectable defects. Do not mix them.

Honor the user's chosen direction within scope and record the reason when it differs from the recommendation. An override cannot make fabricated behavior, endorsement or test results true.
