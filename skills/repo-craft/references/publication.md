# Publication

## One authorization rule

Prepare concrete local assets and verification before external operations. Honor authorization already given for the specific destination and action; do not request it again. Repository presentation work alone does not authorize publishing, uploads, account changes, history rewriting or paid services.

Within existing scope, perform the action after prerequisites pass. Outside scope, finish local work and list the exact pending operation and destination for approval. Missing external authorization does not block safe local preparation.

This applies equally to visibility changes, pushes, release tags, attachments, social preview settings, Pages deployment, profile pins and third-party services. The code host's own settings have no special exception.

## Prepare a reviewable result

1. Identify output and audience. Preserve unrelated files and notices.
2. Verify intended publication content. Inspect sensitive-content signals and rights constraints; do not treat pattern matches as confirmed exposure.
3. Complete README changes, chosen visuals, sources, reproduction commands, relevant documents and local checks. Remove unsupported claims.
4. Record destination, branch or revision, files and exact commands or UI operations. Discover the installed tool's current interface instead of using a private workflow.
5. Execute only operations covered by authorization and whose material checks pass. Observe the actual result.
6. Report local completion and publication separately. A committed asset is not an uploaded preview; a rendered site is not a deployment; a proposed release is not a published release.

Repair failures that contradict the intended claims, or state the limit and narrow the claim before release. Do not default to publishing first and fixing required checks later.

## Sensitive content

Inspect detector hits privately. Confirmed secrets or private data need an exposure-specific remedy. Never rotate credentials, destroy files or rewrite history as a blanket response. Do not publish sensitive reports or raw scanner logs. Continue unaffected preparation and identify actions beyond the authorized remediation scope.

Development fixtures use generated fake credentials only. Do not change production secrets during development. A fresh export can avoid sharing private preparation history; it does not revoke a credential or prove prior exposure was repaired.

## Host behavior

Do not assume when the host exposes preview controls, how it renders video, or whether profile operations depend on visibility. Check the current interface when an authorized operation requires it. A missing optional feature does not require changing visibility.

Uploads remain uploads through draft issues, settings and attachment flows. Never create externally stored assets as a hidden part of testing local presentation.

## Commits and cleanup

Commit focused verified changes under repository instructions. Preserve unrelated work. Stop and verify cleanup of owned render/preview processes. Record remaining external operations and authorization status.
